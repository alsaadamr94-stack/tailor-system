# مِقياس — نظام إدارة محل الخياطة الرجالية

نظام ويب متكامل لإدارة محل خياطة رجالية: العملاء والمقاسات، أوراق العمل وتتبع مراحل
الإنتاج، المخزون (أقمشة ومستلزمات)، العمال وحساب الأجور بالقطعة، التقارير المالية،
والفوترة الإلكترونية المبسطة (ZATCA - المرحلة الثانية).

## المتطلبات
- Node.js نسخة 18 أو أحدث (نزّله من https://nodejs.org إن لم يكن مثبتاً)

## طريقة التشغيل (خطوتان فقط)

```bash
cd backend
npm install
npm start
```

بعد ظهور الرسالة `✅ نظام إدارة محل الخياطة يعمل على: http://localhost:4000`
افتح المتصفح على الرابط: **http://localhost:4000**

النظام يعمل بالكامل من هذا الرابط الواحد (الواجهة + الخلفية + قاعدة البيانات)،
ولا يحتاج تثبيت أي برنامج آخر — قاعدة البيانات هي ملف SQLite ينشأ تلقائياً باسم
`backend/tailor.db` عند أول تشغيل.

## هيكل المشروع

```
tailor-system/
├── backend/                  ← الخلفية (Node.js + Express + SQLite)
│   ├── server.js              نقطة تشغيل السيرفر
│   ├── db.js                  تعريف قاعدة البيانات الكاملة (المخطط)
│   ├── utils/zatca.js         توليد الفاتورة الإلكترونية (UUID, ICV, PIH, QR/TLV)
│   └── routes/                نقاط الوصول (API): عملاء، طلبات، مخزون، عمال، تقارير، فواتير
└── frontend/                  ← الواجهة (React عبر CDN — بدون خطوة بناء Build)
    ├── index.html
    └── app.js                 كل شاشات النظام
```

## الوحدات المتوفرة في النظام

1. **العملاء والمقاسات**: سجل كامل لكل عميل (الاسم، الهاتف، تنبيهات SMS/واتساب)،
   مع إمكانية حفظ أكثر من مقاس لنفس العميل واستعادته عند أي طلب جديد.
2. **الطلبات وأوراق العمل**: رقم تسلسلي فريد لكل طلب، حساب الدفعة المقدمة والمتبقي،
   تحديد تاريخ الاستلام المتوقع تلقائياً حسب ضغط العمل الحالي في المحل.
3. **تتبع مراحل الإنتاج**: جديد ← قيد القص ← قيد الخياطة ← مرحلة الكوي ← جاهز
   للاستلام ← تم التسليم، مع سجل كامل لكل تغيير وتسجيل حالات "تعديل على ثوب جاهز".
4. **توزيع المهام على العمال**: ربط كل طلب بالعامل المسؤول (قصاص/خياط/مكوجي) مع
   حساب الأجرة بالقطعة وتقرير مستحقات كل عامل.
5. **المخزون**: تتبع كمية الأقمشة (بالمتر أو اليارد) وخصمها تلقائياً مع كل طلب،
   بالإضافة لمستلزمات الخياطة (خيوط، أزرار، حشوات، سحابات) وتنبيهات عند الانخفاض.
6. **التقارير المالية**: المبيعات، أرباح الأقمشة، ضريبة القيمة المضافة، ومستحقات العمال.
7. **بطاقة القياس / كارت المعمل**: شاشة طباعة مخصصة (زر "طباعة كارت المعمل") تعرض
   المقاسات والتفاصيل بدون السعر، جاهزة للطباعة الحرارية ودبسها على القماش.
8. **الفوترة الإلكترونية (ZATCA)**: توليد فاتورة مبسطة متوافقة هيكلياً مع متطلبات
   الفوترة الإلكترونية السعودية (راجع القسم التالي).

## الفوترة الإلكترونية (ZATCA) — الوضع الحالي وخطوات الاستكمال

النظام ينفّذ حالياً الجزء البرمجي الداخلي من الفاتورة المبسطة (Simplified Tax
Invoice - B2C):
- **UUID** فريد لكل فاتورة.
- **ICV** عدّاد تسلسلي بدون ثغرات.
- **PIH** تجزئة SHA-256 مرتبطة بالفاتورة السابقة (سلسلة غير قابلة للتعديل).
- **QR Code** بصيغة TLV (Tag-Length-Value) مُحوّل إلى Base64، يحتوي: اسم المحل،
  الرقم الضريبي، تاريخ ووقت الفاتورة، الإجمالي شامل الضريبة، وقيمة الضريبة.

للانتقال إلى الربط الفعلي المُعتمد من هيئة الزكاة والضريبة والجمارك، يلزم إضافة:

1. **CSID Onboarding**: توليد مفتاح خاص (Private Key) وطلب توثيق (CSR)، ثم
   إرساله عبر بوابة فاتورة (Fatoora Portal) للحصول على شهادة الاختبار
   (Compliance CSID) ثم شهادة الإنتاج (Production CSID).
2. **توليد XML بصيغة UBL 2.1** فعلي للفاتورة بدلاً من التمثيل المبسّط الحالي،
   وتوقيعه رقمياً بالشهادة المستلمة.
3. **الربط مع Reporting API** الرسمي لإرسال ملف XML خلال 24 ساعة من إصدار
   الفاتورة المبسطة للعميل.

هذه الخطوات تتطلب حساب فعّال لدى الهيئة ولا يمكن تنفيذها دون بيانات المنشأة
الحقيقية، لذلك تُركت كخطوة تالية موثّقة هنا. البنية الحالية (جدول `invoices`
و`shop_settings` في قاعدة البيانات) مصمّمة لتستوعب هذا الربط دون تعديل جذري.

## تسجيل الدخول والمستخدمون

عند أول تشغيل (`npm start`)، ينشئ النظام تلقائياً حساب مدير افتراضياً بالبريد
`alsaadamr94@gmail.com` وكلمة مرور مبدئية `Tailor@2026` — ستظهر هذه البيانات
أيضاً في نافذة موجه الأوامر عند أول تشغيل. **سجّل الدخول بها ثم غيّر كلمة
المرور فوراً** من صفحة "المستخدمون والصلاحيات" (أو أضف مستخدماً جديداً وامسح
الحساب الافتراضي).

- **مدير**: يرى كل الشاشات بما فيها المستخدمون والإعدادات المالية.
- **موظف**: يرى الشاشات التشغيلية (طلبات، عملاء، مخزون، عمال، تقارير) دون
  إدارة المستخدمين أو إعدادات الفوترة.

يمكنك من صفحة "المستخدمون" إضافة حساب مستقل لكل موظف في المحل (على الكاشير،
على تابلت المعمل، إلخ)، بحيث يدخل كل شخص بحسابه الخاص من أي جهاز.

## التشغيل على الكمبيوتر والجوال معاً (نفس شبكة الواي فاي)

النظام يعمل من جهاز واحد (السيرفر) ويمكن لبقية الأجهزة في نفس شبكة الواي فاي
فتحه من متصفحها مباشرة، دون تثبيت أي شيء عليها:

1. شغّل النظام كالمعتاد (`npm start`) على الكمبيوتر الذي سيبقى مفتوحاً (جهاز
   المحل الرئيسي).
2. اعرف عنوان الشبكة المحلي (IP) لهذا الكمبيوتر:
   - **ويندوز**: افتح موجه الأوامر واكتب `ipconfig`، وابحث عن `IPv4 Address`
     (مثال: `192.168.1.15`).
   - **ماك**: من إعدادات النظام ← الشبكة ← ستجد العنوان أمام الاتصال النشط،
     أو نفّذ `ipconfig getifaddr en0` في Terminal.
3. تأكد أن جدار الحماية (Firewall) يسمح لـ Node.js بالاتصال على المنفذ
   `4000` (عادة تظهر رسالة سؤال عند أول تشغيل، اختر "السماح").
4. من الجوال أو أي جهاز آخر متصل **بنفس شبكة الواي فاي**، افتح المتصفح واكتب:
   ```
   http://192.168.1.15:4000
   ```
   (استبدل الرقم بعنوان جهازك الفعلي من الخطوة 2).
5. سجّل الدخول بحساب المستخدم الخاص بذلك الجهاز/الموظف.

> ملاحظة: هذا يعمل فقط داخل نفس شبكة الواي فاي (أي داخل المحل). إذا انقطع
> اتصال الكمبيوتر الرئيسي بالكهرباء أو أُغلق، يتوقف النظام عن جميع الأجهزة.

## الوصول من خارج المحل (عبر الإنترنت من أي مكان)

إذا أردت فتح النظام من جوالك خارج شبكة المحل (وليس فقط داخله)، لديك خياران:

**الخيار الأول — سريع ومؤقت (تجربة فقط):** استخدام أداة مثل `ngrok` تعطيك
رابطاً مؤقتاً على الإنترنت يوجّه لجهازك المحلي. مناسب للتجربة وليس للاستخدام
الدائم (الرابط يتغيّر كل مرة في النسخة المجانية).

**الخيار الثاني — دائم واحترافي عبر Render.com (خطوات مفصّلة):**

⚠️ **مهم قبل البدء:** خطة Render "المجانية" الحقيقية لا تحفظ ملف قاعدة
البيانات بشكل دائم — أي بيانات تدخلها (عملاء، طلبات) قد تُمسح عند أي تحديث
أو إعادة تشغيل للسيرفر، لأن التخزين فيها مؤقت (Ephemeral). لحفظ بيانات محل
حقيقي بأمان يلزم **خطة Starter المدفوعة (حوالي 7$ شهرياً)** مع "قرص دائم"
(Persistent Disk). إن كنت تريد $0 فعلياً وبياناتك لا تُفقد أبداً، فالخيار
الأنسب هو البقاء على التشغيل المحلي عبر شبكة الواي فاي (الموضح أعلاه). فيما
يلي خطوات النشر على Render بالطريقة الآمنة (المدفوعة):

1. **أنشئ حساب GitHub** (إن لم يكن لديك) على github.com بنفس بريدك
   `alsaadamr94@gmail.com`، وأنشئ مستودعاً (Repository) جديداً باسم مثلاً
   `tailor-system`.
2. **ارفع مجلد المشروع كاملاً** (`tailor-system` بكل ما فيه، بما في ذلك ملف
   `render.yaml` المرفق) إلى ذلك المستودع. إن لم تكن معتاداً على Git، أسهل
   طريقة هي استخدام تطبيق GitHub Desktop (github.com/apps/desktop):
   ثبّته → "Add Local Repository" → اختر مجلد `tailor-system` → "Publish repository".
3. **أنشئ حساباً على render.com** بنفس البريد `alsaadamr94@gmail.com`، واربطه
   بحساب GitHub الخاص بك عند الطلب.
4. من لوحة Render: **New +** → **Blueprint** → اختر مستودع `tailor-system`
   الذي رفعته. سيقرأ Render ملف `render.yaml` تلقائياً ويقترح عليك إنشاء
   الخدمة بكل إعداداتها (اسم الخدمة، القرص الدائم، متغيرات البيئة) دفعة واحدة.
5. عند الطلب، **عيّن قيمة `ADMIN_DEFAULT_PASSWORD`** (كلمة مرور المدير
   الأولى) بنفسك بدلاً من القيمة الافتراضية في الكود — هذا حقل سري يطلبه
   Render قبل النشر.
6. اضغط **Apply / Deploy**. انتظر بضع دقائق حتى تكتمل عملية البناء والنشر
   (ستظهر السجلات (Logs) مباشرة في الصفحة).
7. بعد اكتمال النشر، سيعطيك Render رابطاً دائماً شبيهاً بـ:
   `https://tailor-system.onrender.com` — هذا هو رابط نظامك على الإنترنت،
   يعمل من أي جوال أو كمبيوتر وفي أي مكان بالعالم دون شبكة واي فاي مشتركة.
8. سجّل الدخول بالبريد وكلمة المرور اللذين حدّدتهما، ثم غيّرها فوراً من
   صفحة "المستخدمون والصلاحيات" وأنشئ حساباً لكل موظف.

**بعد النشر — كيف تحدّث النظام لاحقاً؟** أي تعديل تريده على الكود مستقبلاً:
عدّل الملفات محلياً → ادفعها (Push) إلى نفس مستودع GitHub → سينشر Render
النسخة الجديدة تلقائياً خلال دقائق، دون أي إجراء يدوي إضافي.



## ملاحظات تقنية
- الواجهة مبنية بـ React عبر CDN مباشرة (بدون Webpack/Vite) لتشغيل فوري بلا
  خطوات بناء إضافية؛ مناسبة لحجم الاستخدام في محل واحد.
- قاعدة البيانات SQLite ملف واحد يسهل نسخه احتياطياً (`backend/tailor.db`).
  للانتقال إلى PostgreSQL لاحقاً عند الحاجة لتعدد الفروع/المستخدمين المتزامنين،
  المخطط في `db.js` مصمم بأسماء وأنواع أعمدة متوافقة منطقياً مع PostgreSQL.
- لأخذ نسخة احتياطية: انسخ ملف `backend/tailor.db` فقط.
