# مِقياس — نظام إدارة محل الخياطة الرجالية

نظام ويب متكامل لإدارة محل خياطة رجالية: العملاء والمقاسات، أوراق العمل وتتبع مراحل
الإنتاج، المخزون (أقمشة ومستلزمات)، العمال وحساب الأجور بالقطعة، التقارير المالية،
تسجيل دخول متعدد المستخدمين بالصلاحيات، والفوترة الإلكترونية المبسطة (ZATCA - المرحلة الثانية).

## المتطلبات
- Node.js نسخة 18 أو أحدث (نزّله من https://nodejs.org إن لم يكن مثبتاً)

## طريقة التشغيل محلياً (خطوتان فقط)

```bash
npm install
npm start
```

بعد ظهور الرسالة `✅ نظام إدارة محل الخياطة يعمل على: http://localhost:4000`
افتح المتصفح على الرابط: **http://localhost:4000**

النظام يعمل بالكامل من هذا الرابط الواحد (الواجهة + الخلفية + قاعدة البيانات)،
ولا يحتاج تثبيت أي برنامج آخر — قاعدة البيانات هي ملف SQLite ينشأ تلقائياً باسم
`tailor.db` عند أول تشغيل.

## هيكل المشروع

```
tailor-system/
├── server.js                  ← نقطة تشغيل السيرفر (الخلفية + الواجهة معاً)
├── db.js                      ← تعريف قاعدة البيانات الكاملة (المخطط)
├── package.json
├── render.yaml                ← إعداد جاهز للنشر على Render (اختياري)
├── utils/
│   ├── zatca.js                توليد الفاتورة الإلكترونية (UUID, ICV, PIH, QR/TLV)
│   └── auth.js                 تشفير كلمات المرور وجلسات الدخول (JWT)
├── routes/                    ← نقاط الوصول (API): عملاء، طلبات، مخزون، عمال، تقارير، فواتير، مستخدمون
└── public/                    ← الواجهة (React عبر CDN — بدون خطوة بناء Build)
    ├── index.html
    └── app.js
```

كل شيء الآن في مجلد واحد مسطّح (بدون مجلدات فرعية متداخلة) — هذا يجعل رفع
المشروع لأي منصة استضافة أبسط وأقل عرضة لأخطاء "الملف غير موجود".

## الوحدات المتوفرة في النظام

1. **العملاء والمقاسات**: سجل كامل لكل عميل، مع إمكانية حفظ أكثر من مقاس لنفس
   العميل واستعادته عند أي طلب جديد.
2. **الطلبات وأوراق العمل**: رقم تسلسلي فريد لكل طلب، حساب الدفعة المقدمة
   والمتبقي، وتحديد تاريخ الاستلام المتوقع تلقائياً حسب ضغط العمل الحالي.
3. **تتبع مراحل الإنتاج**: جديد ← قيد القص ← قيد الخياطة ← مرحلة الكوي ← جاهز
   للاستلام ← تم التسليم، مع سجل كامل لكل تغيير وتسجيل "تعديل على ثوب جاهز".
4. **توزيع المهام على العمال**: ربط كل طلب بالعامل المسؤول مع حساب الأجرة
   بالقطعة وتقرير مستحقات كل عامل.
5. **المخزون**: تتبع كمية الأقمشة وخصمها تلقائياً مع كل طلب، بالإضافة
   لمستلزمات الخياطة وتنبيهات عند الانخفاض.
6. **التقارير المالية**: المبيعات، أرباح الأقمشة، ضريبة القيمة المضافة،
   ومستحقات العمال.
7. **بطاقة القياس / كارت المعمل**: شاشة طباعة مخصصة تعرض المقاسات بدون السعر.
8. **تسجيل الدخول والمستخدمون**: راجع القسم التالي.
9. **الفوترة الإلكترونية (ZATCA)**: راجع القسم الخاص بها أدناه.

## التشغيل على الكمبيوتر والجوال معاً (نفس شبكة الواي فاي) — مجاني بالكامل

1. شغّل النظام (`npm start`) على الكمبيوتر الذي سيبقى مفتوحاً (جهاز المحل الرئيسي).
2. اعرف عنوان الشبكة المحلي (IP): على **ويندوز** اكتب `ipconfig` في موجه
   الأوامر وابحث عن `IPv4 Address` (مثال: `192.168.1.15`). على **ماك**:
   إعدادات النظام ← الشبكة، أو `ipconfig getifaddr en0` في Terminal.
3. اسمح لـ Node.js بالمرور عبر جدار الحماية عند أول تشغيل (اختر "السماح").
4. من الجوال أو أي جهاز آخر على **نفس شبكة الواي فاي**، افتح المتصفح واكتب:
   `http://192.168.1.15:4000` (بعنوانك الفعلي).
5. سجّل الدخول بحساب المستخدم الخاص بذلك الجهاز.

> هذا يعمل فقط داخل شبكة المحل. إذا أُغلق الكمبيوتر الرئيسي يتوقف النظام عن الجميع.

  بدلاً من SQLite — وهي مضمونة الاستمرارية عبر إعادة النشر. أخبرني إن أردت
  ذلك وسأنفّذه.

## الفوترة الإلكترونية (ZATCA) — الوضع الحالي وخطوات الاستكمال

النظام ينفّذ حالياً الجزء البرمجي الداخلي من الفاتورة المبسطة (Simplified Tax
Invoice - B2C):
- **UUID** فريد لكل فاتورة.
- **ICV** عدّاد تسلسلي بدون ثغرات.
- **PIH** تجزئة SHA-256 مرتبطة بالفاتورة السابقة (سلسلة غير قابلة للتعديل).
- **QR Code** بصيغة TLV (Tag-Length-Value) مُحوّل إلى Base64.

للانتقال إلى الربط الفعلي المُعتمد من هيئة الزكاة والضريبة والجمارك، يلزم:

1. **CSID Onboarding**: توليد مفتاح خاص وطلب توثيق (CSR) عبر بوابة فاتورة
   (Fatoora Portal) للحصول على شهادة الاختبار ثم شهادة الإنتاج.
2. **توليد XML بصيغة UBL 2.1** فعلي وتوقيعه رقمياً بالشهادة المستلمة.
3. **الربط مع Reporting API** الرسمي لإرسال ملف XML خلال 24 ساعة من الإصدار.

هذه الخطوات تتطلب حساب فعّال لدى الهيئة ولا يمكن تنفيذها دون بيانات المنشأة
الحقيقية. البنية الحالية (جدولا `invoices` و`shop_settings`) مصممة لتستوعب
هذا الربط دون تعديل جذري.
